# 机联智检 Chrome 侧栏 · 0.4.0 开发版

这是 Chrome Manifest V3 插件源码，配合本机机联智检网页后端使用，不能单独替代后端。当前使用项目中的 `extension` 文件夹，可连接当前源码网页。源码与封存插件包的 manifest 版本均为 `0.4.0`，但当前源码已修正 CMD 启动提示；封存 ZIP 保留原内容，未重新打包。

## 安装与连接

1. 使用当前项目的 `extension` 文件夹，确认其中直接包含 `manifest.json`，不需要编译或解压旧软件包。
2. 在 Chrome 打开 `chrome://extensions/`，启用开发者模式，选择“加载已解压的扩展程序”，选中这个 `extension` 文件夹。源码更新后在扩展管理页点击“重新加载”。
3. 在项目根目录的 CMD 运行 `start_local.cmd --port 8892`。当前网页地址为 `http://127.0.0.1:8892/assistant-ui/`；打开插件“连接设置”，选择8892并连接。该入口使用已有 Python，不修改 PowerShell 策略；服务已运行时会报告地址。若直接运行不带参数的 `start_local.cmd`，默认端口为8890，插件也应选择8890。
4. 打开 Trackunit 设备详情页，点击插件图标，再点击“读取当前设备”。列表页和管理页不识别为设备。
5. 等待“已关联”确认，在下方核对机型、来源、采样时间。如果存在多个数据版本，先选择版本。没有匹配数据时先同步或导入，插件不会选用其他设备替代。

支持 `manager.trackunit.com` 和 `new.manager.trackunit.com` 下 `/assets/<UUID>` 路径。只提取设备 ID，不复制页面查询参数、页面文字或登录令牌。`activeTab` 授权依赖用户点击插件；跨网站导航后可能需要再次点击插件图标。

## 工作方式

网页与插件共用设备趋势、故障资料、本地备件候选、排查任务、草稿、AI 分析、历史记录和 XGSS 页面入口。插件只承担平台设备识别与网页承载，数据、密钥和报告留在后端管理。

读取 ID 后先显示等待匹配；收到网页对相同设备和版本的确认后才显示已关联。切换浏览器标签或页面后提示保留旧设备，需重新读取。上一次分析尚未结束时，先完成原操作再切换设备。较旧网页没有确认协议时，插件会提示未收到确认，不推断为已关联。

重新连接、修改端口、关闭浏览器可能丢失未保存输入。操作前使用网页中的“保存本机草稿”或保存排查任务记录。
