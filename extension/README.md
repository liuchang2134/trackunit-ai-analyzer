# 机联智检 Chrome 侧栏 · 0.4.2 开发版

这是 Chrome Manifest V3 插件源码，配合本机机联智检网页后端使用。当前 `extension` 文件夹源码版本为 `0.4.2`；历史封存 ZIP 保留原内容，没有重新打包。本工具采用蓝白配色，是独立辅助工具，并非徐工官方产品。

## 安装与连接

1. 使用当前项目的 `extension` 文件夹，确认其中直接包含 `manifest.json`，不需要编译或解压旧软件包。
2. 在 Chrome 打开 `chrome://extensions/`，启用开发者模式，选择“加载已解压的扩展程序”，选中这个 `extension` 文件夹。源码更新后在扩展管理页点击“重新加载”。
3. 在项目根目录的 CMD 运行 `start_local.cmd --port 8892`，保持服务运行。网页地址为 `http://127.0.0.1:8892/assistant-ui/`。插件优先尝试此前保存的端口；初次使用先尝试8892，未收到完整握手再尝试8890。可在“连接设置”修改优先端口。自动回退不覆盖保存的偏好。启动入口使用已有 Python，不修改 PowerShell 策略；服务已运行时会报告地址。不带参数的 `start_local.cmd` 默认端口为8890。
4. 点击“演示案例”即可查看预设的五阶段模拟排查，无需 Trackunit 设备页，也不会触发外部 API 调用。已连接的工作区切换到演示前会提示保存草稿并确认继续。
5. 打开 Trackunit 设备详情页，点击插件图标，再点击“读取当前设备”。列表页和管理页不识别为设备。
6. 等待“已关联”确认，在下方核对机型、来源、采样时间。如果存在多个数据版本，先选择版本。没有匹配数据时先同步或导入，插件不会选用其他设备替代。

支持 `manager.trackunit.com` 和 `new.manager.trackunit.com` 下 `/assets/<UUID>` 路径。只提取设备 ID，不复制页面查询参数、页面文字或登录令牌。`activeTab` 授权依赖用户点击插件；跨网站导航后可能需要再次点击插件图标。

## 工作方式

网页与插件共用设备趋势、故障资料、本地备件候选、排查任务、草稿、AI 分析、历史记录和 XGSS 页面入口。插件只承担平台设备识别与网页承载，数据、密钥和报告留在后端管理。

连接使用两个获准本机端口的 iframe 握手，不新增网络或站点权限。只有来自当前 iframe、当前端口和当前连接编号的网页就绪、运行配置消息都到达后，才显示工作区。连接期间显示状态卡；两个端口都失败时移除 iframe 地址，显示启动命令和“重新连接”，避免停留在浏览器灰色错误页。“已连接”仅表示本机页面与后端配置已确认，模型是否可用仍以实际分析结果为准。

读取 ID 后先显示等待匹配；收到网页对相同设备和版本的确认后才显示已关联。切换浏览器标签或页面后提示保留旧设备，需重新读取。上一次分析尚未结束时，先完成原操作再切换设备。较旧网页没有确认协议时，插件会提示未收到确认，不推断为已关联。

同一工作区内读取新设备采用 hash 切换，保留网页的草稿保护和正在进行的分析，并重新等待设备确认。从演示返回设备、重新连接或修改端口会重新载入网页。操作前使用网页中的“保存本机草稿”或保存排查任务记录。关闭浏览器也可能丢失未保存输入。

## 验证状态

0.4.1 已通过模拟消息、端口回退、双端口超时、过期握手拒绝、设备确认与演示切换测试。网页中的设备隔离、版本选择、输入保留与延后切换此前已通过独立浏览器测试。**当前已安装的 Chrome 插件仍需用户在扩展管理页重新加载，并确认真实侧栏能够连接；本轮没有完成真实 Chrome 插件重载后的握手验收。** 浏览器工具不允许访问扩展内部页面，未使用替代路径绕过限制。

0.4.2 的网页默认使用 DeepSeek，侧栏显示后端返回的实际模型；仍可在后端配置中选择 Gemini 或本地模型。模拟案例保持离线预设，不会调用这些 AI 接口。密钥已配置、插件已连接均不代表 AI 排查已成功，完整请求结果以网页中的最近排查记录为准。

XGSS 通用入口已使用既有身份、type 与公钥成功认证，并在 Chrome 测试容器中显示官方 VIN 和图册目录；还需确认故障码字段、类型及加密位置，完成正式设备交接与对应手册验收。插件不包含账号、公钥、API 密钥、真实设备缓存或诊断记录。官方页面可显示，不代表 AI 已读取手册或取得可供自动匹配的 BOM／库存接口。
