# 待处理工作台与设备排查任务

网页入口 http://127.0.0.1:8892/assistant-ui/ ，启动以源码 README 的 CMD 步骤为准。本功能首次验收于 2026-09-14 的 `20260914.13-maintenance-worklist` 构建；当前进度以源码中的 `docs/PROJECT_ACCEPTANCE_STATUS.md` 为准。

## 实际操作

1. 首页“待处理”显示本机进行中的排查任务，以及已载入设备记录中需要核对的数据版本。
2. 点击“进入设备”，核对设备、来源和数据版本；在设备旁点击“排查任务”建立任务。没有告警记录的设备也可通过“查找所有设备”进入后建立任务。
3. 填写本次检查结果或进度说明，选择待开始、排查中、待补充或已归档，再点击“保存记录与进度”。每次保存都追加历史，更新和归档必须有说明。
4. 从工作台“继续处理”可以恢复已保存任务。归档任务位于“已归档”范围；选择其他进度并填写原因可以重新打开。同一设备、来源与数据版本只能有一条未归档任务。
5. “查看设备证据”进入原设备工作区，继续查看趋势、故障和本地备件资料。“带记录进入 AI 排查”把初始描述和最近三条有文字的已保存记录带入表单，保留该设备已有问题和观察，不会自动请求 Gemini。尚未保存的记录需先保存成功才能交接。超出表单长度时会提示整理，不会截断原始记录。
6. “导出任务记录”下载 Markdown，包含建立时设备摘要、来源、数据版本及完整处理历史。当前已有同设备、同来源、同版本的 AI 报告时，可以随记录关联其编号；真实 Gemini 成功链路仍未验收。

## 进度与故障状态

任务进度由本机操作人填写，表示这次排查如何推进。设备故障状态来自已载入数据，始终保持原样。因此归档任务后，“设备记录待核对”仍可能显示该设备。任务归档不表示设备已经修复，也不自动确认故障根因、备件适配或维修效果。

“设备数据来源”只筛选下方的设备记录；上方任务始终各自标注来源。“进行中”包含待开始、排查中和待补充。列表每页 20 条。

## 保存与恢复

- 记录存放在本机 `data/local/maintenance-cases.sqlite3`，不需要 AI、Trackunit 或 XGSS 在线请求。
- SQLite 事务中检查修订号，历史与进度同时提交。旧页面或并发保存返回冲突，输入保留，重新读取后可核对再保存。
- 任务窗口的未保存输入按任务和设备版本暂存在当前页面中；关闭窗口、切换设备再回来可以恢复。刷新或关闭整个页面前仍需要保存。
- 对应设备版本暂不可用时，任务仍可阅读、追加记录和导出；进入设备证据或 AI 交接不可用，不会替换为其他设备。

这是一套本机排查记录功能，尚未接入正式工单系统、多人身份、库存或采购流程。模型和官方接口未完成的部分仍按项目验收清单单独验收。
