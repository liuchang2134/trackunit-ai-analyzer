# 机联智检本地助手 · 开发版

## 启动

当前安装与启动以 [README](../README.md#启动) 为准。已有 Python 环境时，在项目根目录的 CMD 运行 `start_local.cmd --port 8892`，打开 http://127.0.0.1:8892/assistant-ui/ 。
默认 AI_PROVIDER=gemini，使用 gemini-flash-latest 云端推理。GEMINI_API_KEY 保存在本机被 Git 忽略的 .env；所选设备证据、问题和检查反馈经后端发送到 Google Gemini，报告保存在本机。模型不可用时显示失败，不自动切回本地模型。
后端只监听 127.0.0.1，不用于共享服务器或公网部署。

首次克隆按 README 的 CMD 步骤使用 Python 3.12 安装依赖；首次安装需要互联网。演示和本机记录功能不要求配置 Gemini 密钥，真实云端分析需要可用的 API key。运行 `start_local.cmd --port 8892 --check-only` 可检查现有环境与同端口服务，不调用外部 API。

只有首次配置且没有 `.env` 时才复制示例；已有配置应保留。仅演示模拟数据时不需要 Trackunit 凭据。运行 `scripts/check_local_runtime.py` 可检查 Python、依赖、密钥是否配置与官方端点（不代表鉴权或配额已验证），不读取真实设备数据。启动脚本优先使用 `.venv`，兼容本机开发环境 `.tmp/venv`；服务已运行时复用现有服务。
复制 `.env.example` 为 `.env` 并在本地填写 Trackunit 凭据。不要把它放进 extension 目录。

启动入口核对同一应用与当前构建，已有匹配服务时报告入口地址；端口被其他或旧服务占用时明确报错，不停止或重启它。Chrome 侧栏连接设置应与启动端口一致，使用上述命令时选择 8892。当前构建、接口核查和真实侧栏验收范围见 [当前验收状态](PROJECT_ACCEPTANCE_STATUS.md)；本机页面可用不等于 AI 完整链路通过。

## 侧栏

在 Chrome / Edge 的扩展管理页启用开发者模式，选择“加载已解压的扩展程序”，选择项目的 `extension` 目录。
点击扩展图标打开侧栏，再点击“读取当前设备”，从受支持的 Trackunit 设备详情网址读取设备 ID，并与本地数据匹配；多个版本需明确选择。切换平台设备后需重新读取，当前不持续跟随，也不抓取整页内容。也可在本地工作区手动选择设备。
当前 0.4.0 扩展声明 sidePanel 和 activeTab 权限，后者由点击图标临时授权以读取当前标签页 URL。扩展不保存 Trackunit 或 Gemini 密钥；AI 调用由本机后端转发到 Gemini，详见 [插件说明](../extension/README.md)。
尚需在 Chrome / Edge 实际加载扩展验证；普通浏览器页面通过不代表扩展验收完成。

## 查找设备

当前开发版在设备旁提供“查找设备”，支持机型、序列号、设备编号及片段名称搜索，按实测/模拟来源和未解决/状态冲突记录筛选。每个数据版本分别列出，选择后才切换工作区；搜索及 Esc 关闭不会改换设备。故障摘要可直接定位故障记录。平台设备上下文仍只允许对应实测版本。设备查找的本机历史验收记录，不随源码分发：`docs/evaluation/2026-09-14-device-finder.md`。

## 分析流程

选择设备后先查看“运行数据与故障记录”：工时/怠速/燃油曲线可切换指标、时段并缩放，数据表可查看绘图依据。该面板只读本地记录，不调用 AI。缺失值留空，不按零显示；统计基于完整载入时段的可用区间，不随图表缩放变化。点击故障行“重点排查”会带入故障码并聚焦问题，点击开始分析才请求 Gemini。

选择设备与预设任务后可直接开始；问题和现场检查结果选填。自由提问需要填写问题。运行时显示实际等待秒数；完成后定位报告，失败保留同一设备之前的报告。诊断记录默认按当前设备和当前数据版本筛选。模型最多进行 6 步决策，
可读取快照、故障记录和本地备件目录。模型不可执行任意代码、URL 或设备控制。
结果包括工具记录和来源 ID。来源 ID 校验只能防止引用不存在的证据，不保证模型推论正确。
无模型或输出无效时明确显示失败，不用规则报告冒充 AI。

Gemini 的明确任务先由本机读取所需快照、故障和趋势；备件部件范围与诊断结论仍由模型选择，自由提问保留逐步工具选择。模型每次决定最多尝试 3 次，仅对 HTTP 500/502/503/504 临时服务器错误重试，退避 2/4 秒加少量随机延迟，并受请求剩余时间限制。鉴权、请求格式、额度和不确定超时不自动重试；不切换模型或服务商。整次排查时限 120 秒，完成报告记录 model_decisions 与 duration_seconds；本地预读与模型选择分别记录在 tool_trace.trigger 中。新版实际 Gemini 联调记录见 evaluation/2026-09-14-gemini-bounded-live.json。

## 备件资料

故障行的“查看资料”直接打开本地目录查询，展示对应故障记录、候选、机型/序列号限制、资料出处、页码、版本和目录检查原文；不调用 AI。候选以精确故障码及适用范围筛选，不进行语义推断。无匹配显示具体过滤原因。XGSS 尚未接通时不伪造手册地址。详情内的 AI 入口只填入问题，点击开始分析才提交。

切换设备或数据版本会清除旧详情。问题、现场观察、任务、语言和续查关系按设备/版本/来源保留本页草稿，切回来恢复；刷新或关闭页面清空。未提交草稿不等于已保存的检查反馈或诊断记录。

`docs/examples/demo-parts-catalog.json` 是导入示例，零件号以 DEMO- 开头，禁止用于采购。
真实目录使用 provenance=user_supplied，并填写 part_number、name、component、models、
checks、source_document、source_page、revision。fault_codes 是可选精确匹配。
限制序列号时设 applicability=serial_list 并填 serial_numbers；否则 model_only，
结果会标为序列号未验证。当前不支持序列号区间、替代件链或配置选装约束。
同号同内容重复导入不新增；冲突拒绝，不静默覆盖。目录保存在 Git 忽略的 data/local/parts.json。

## 时序证据工具

AI 可调用 trends 计算时间窗口内工时增量和怠速占比，并检查旧数据、计数器重置和重复事件。
这是一套可解释筛查规则，不是经过真实故障标注校准的预测模型。
仅有快照时返回数据不足，不把累计怠速/累计工时直接当作近期利用率。
真实缓存缺少故障或遥测文件时不再混入演示数据。


## 导入历史工况

侧栏“导入工况数据”支持 JSON 和规范化 CSV。导入后自动切换到新数据集，并显式显示“导入模拟数据”或“导入实测 / 未验证”。导入文件保存到 data/local/datasets，不覆盖真实车队缓存，也不提交到 Git。

JSON 示例：docs/examples/excavator-shift.json。它由 scripts/export_demo_dataset.py 从模拟数据集的公开观测记录转换，不读取 evaluator_only、故障答案或未来记录。当前例子是一个截断工况片段，不是完整八小时班次。界面报告引用 dataset_id、source_document 和 replay_at。

CSV 第一行允许列：recorded_at,operating_hours,idle_hours,fuel_remaining_percent,engine_status。recorded_at 必填且须包含时区；其余允许空白。工时单位为小时，燃油为 0–100 百分比，engine_status 为 running/stopped/unknown。CSV 使用当前选择设备的资料及手动选择的数据来源。单文件最多 10000 条记录；页面最多 3MB。

模拟 JSON 可指定 replay_at，以当时可见数据评估；禁止包含晚于该时间的记录。实测导入不允许用 replay_at 重定义当前时间。没有模型实测验证过的故障概率，也不把导入数据自动视作厂家认证资料。

## 接口核验结果
“数据与备件库”展示上次人工核验的接口结果、时间与记录数。它读取本地 data/local/integration-status.json，不发送新的 Trackunit 请求；超过24小时会提示过期。核验只覆盖当时选定设备与查询窗口，不保证整车队权限、当前在线状态或完整故障覆盖。缺失或损坏的核验文件显示未核验。

## 提交前 AI 状态

排查表单上方显示本机保存的最近完整排查结果、时间与失败类别。“更新状态”不调用 AI，不代表当前可用性，也不承诺额度恢复。状态在切换设备后保留；历史联调记录明确标记为当时配置，当前配置未核验。故障资料的继续排查按钮紧随状态，原文和接入细节按需展开。详见 [状态记录规则](AI_REQUEST_STATUS.md)。本机历史验收记录，不随源码分发：`docs/evaluation/2026-09-14-ai-request-status.md`。

## 本地诊断记录
成功分析会保存到 data/local/investigations，包含原问题、现场观察、输入数据集、结果与证据。内容哈希作为记录ID，重复相同记录不新增，后续分析不会修改旧记录。“诊断记录”默认显示当前设备与数据版本最近50条摘要，也可主动切换全部设备，可导出完整JSON。历史报告不代表当前设备状态；本地文件可能包含业务数据，不随公开提交包分发。文件损坏会标记不可读；保存失败时仍返回分析结果并提示用户导出备份。此前运行的报告不会自动补存。

## 分析任务
分析前可选择综合排查、故障与备件查询、工时与怠速趋势、设备概况或自由提问。综合排查要求读取快照、故障、趋势和备件；备件查询不能跳过故障和目录工具。已返回的目录条目可直接作为引用。此检查确认必要数据查询已执行，不能证明模型全部文字结论正确。自由提问仅有有限关键词识别，具体任务优先使用明确选项。

## 绘图数据下载

展开“查看绘图数据”可下载所选指标、所选时段的 CSV。文件含设备、型号、序列号、数据版本、来源、单位及图表内容校验值；缺失值为空，时间为带时区 ISO 格式。滑块缩放不改变导出范围，若服务端数据更新则要求重新载入图表。已用浏览器下载并检查 61 行模拟工时、36 行缺失怠速实测记录。

## Gemini 额度错误

额度处理规则在 2026-09-14 的 `20260914.11-ai-request-status` 构建中已有验证；该版本号属于历史时点，当前版本见 [当前验收状态](PROJECT_ACCEPTANCE_STATUS.md)。429 响应不会自动重试；程序只提取可识别的额度窗口、计量单位和数值上限，不向界面返回原始响应、项目编号或凭据。每日请求额度耗尽不会采用短暂的 RetryInfo 提示作为恢复承诺；每分钟限制可显示服务端建议的最短等待时间，但不保证下一次成功。

2026-09-14 09:41 UTC 的实际请求返回当时模型每日免费请求限额 20 次已耗尽。这是该次请求与配置的历史结果，不代表当前额度或恢复时间；后续核查见当前验收状态。请以 Google 项目额度状态为准，本机趋势、故障资料和目录查询不依赖这次模型调用。
