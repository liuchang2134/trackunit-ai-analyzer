# 本机排查草稿

当前源码可在 AI 成功生成报告之前，保存问题、现场检查记录、任务、报告语言、人工故障码及原诊断关联。入口在排查表单的现场记录下方。保存不调用 AI。

1. 选择设备和数据版本，填写问题、现场观察或关联适用的故障码，点击“保存本机草稿”。只有故障码也可以保存。看到保存时间及“当前输入已保存”才表示保存完成。
2. 刷新或重新打开网页后，选择同一设备与数据版本，点击“恢复已存草稿”。已存内容可先展开查看；恢复后焦点回到记录输入处。
3. 当前输入会被已存内容替换；“撤销恢复”可取回恢复前的输入。编辑后的内容需要再次点击保存。
4. 如果另一页面已保存新版本，旧页面保存会收到冲突提示。先“重新读取草稿”，查看并恢复新版本，再编辑保存。不会自动覆盖另一页面的记录。

故障码恢复为待确认的参考资料。核对当前设备型号与协议版本后，点击“带入本次排查”，或者移除该代码后再分析。恢复、撤销恢复及异步查码都不会沿用上一台设备的确认，也不会用迟到的查询结果覆盖新文字。草稿存的是人工输入；资料暂时缺失时仍保留已存内容，AI 查码时另行核对定义与来源。

草稿仅保存在本机后端的 `data/local/investigation-drafts/`，按设备编号、序列号、数据来源及导入数据版本隔离。不同浏览器连接同一本机后端可读取它；不是浏览器缓存，也没有云端同步。仅保存通过字段白名单的输入，不记录 API 配置或凭证；该目录被 Git 和软件包排除。

每个范围保留一份可编辑草稿。它不是不可变维修档案或完成的诊断报告；保存不调用 Gemini，不改变机器故障状态。用户点击“开始分析”时，现有分析流程才会将问题和现场记录发送给配置的模型。原有报告反馈记录仍按原流程保存。

尚未保存的编辑仍只存在当前页面，刷新后会清空。当前实现和并发冲突测试针对现有单进程本机后端；没有验证多个后端进程同时写同一草稿目录。服务器存储不可用时会明确报错，保留当前输入及上一次已存记录。

本轮后端API测试验证真实本地文件保存与原子更新；Chrome界面测试使用独立的内存草稿响应，验证故障码保存、刷新恢复、重新确认与失败时保留输入。本机证据为 `data/local/core-browser-check/result.json`。封存 v10 ZIP 与既有参赛文件未包含这次故障码草稿更新；原始草稿功能的本机历史验收记录，不随源码分发：`docs/evaluation/2026-09-14-local-drafts.md`。
