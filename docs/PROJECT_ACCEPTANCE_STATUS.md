## 历史：修掉「历史报告拿不到 AI 检索词」（2026-09-15）

网页构建 `20260915.20-docs-index`，插件源码 `0.9.1`，包 `dist/jilian-extension-0.9.1.zip`。

端到端联动验证（侧栏 → 工作区 → AI 检索词）时，**查出一个真实功能缺陷**。

- **症状**：从「诊断记录」打开一份含 AI 分析的历史报告后，工作区回答侧栏的检索词请求时给出 **`has_report: false`、0 个检索词**。侧栏于是显示"尚无 AI 建议。请先在工作区完成一次 AI 分析"——**而报告就在屏幕上**。用户因此无法在图册上标注 AI 目标，而这正是本项目的核心动作。
- **根因**：`report` 变量只在**新分析完成时**赋值；历史重开走的是 `refreshHistory()` 里另一条渲染路径，**从不发布它正在显示的那份报告**。
- **修法**：新增独立的 `openedReport`，`currentAISearchGuidance()` 取 `report || openedReport`；历史打开时发布该报告，`clearReport()` 一并清空。**刻意不覆盖 `report`**——那样会把流程条、导出与反馈面板悄悄切到历史快照上。
- **顺带修正两处会误导用户的标志**：`has_report` 原本只反映当前运行，`fault_code` 也取自当前运行。现改为以**实际提供检索词的那份报告**为准，并新增 `has_search_terms`，让侧栏能区分"没有报告"与"有报告但没有检索词"。
- **实测修复效果**（真实 Chrome，打开真实历史报告）：

| | 修复前 | 修复后 |
|---|---|---|
| 检索词 | 0 | **12** |
| 部件假设 | 0 | **4** |
| `has_report` | false | **true** |
| 故障码 | null | **E4030** |

- **回归**：**774 项 Python 通过（0 跳过）**、170 项 Node 通过；新增 6 项契约测试（`tests/test_guidance_from_history.py`），跨 `app.js` 与 `panel.js` 锁住这条接缝——缺陷正是出在两个文件之间。
