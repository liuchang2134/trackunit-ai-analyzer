# 故障与备件匹配演示

本案例仅用于展示软件流程。工时来自已有模拟工况，两个告警由人工注入；不代表真实设备故障、传感器失效机理或制造商诊断规则。DEMO-BOOST-SENSOR 不是采购零件号。

## 准备

在项目根目录运行：

```powershell
.venv/Scripts/python.exe scripts/prepare_parts_demo.py --install
```

命令在内存中构造案例，并将它与演示目录导入本地存储；`--install` 不改写包内示例文件。相同数据重复导入不会重复创建记录；目录冲突会报错，不会覆盖已有条目。不会修改 Trackunit 缓存。若开发时需要重新导出示例 JSON，去掉 `--install` 单独运行。

## 展示步骤

1. 打开本地助手，点击“刷新设备”，选择“演示：增压信号告警与备件排查”。确认数据来源是“导入模拟数据”。
2. 输入：“读取故障记录，检索对应备件目录，给出候选、依据和换件前的检查。不要确认根因。”
3. 查看工具记录，应包含 snapshot、faults、parts；模型也可以读取 trends。
4. 查看备件表：演示增压压力传感器、DEMO-BOOST-SENSOR、故障码匹配、序列号适用性待确认，以及人工演示目录出处。
5. 展开“补充现场检查记录”，输入实际演示观察，再重新分析；观察属于用户提供的未验证证据。
6. 导出报告。讲解时强调：告警是检查线索，备件是候选，必须核实线束、接头、测量结果和整机配置。

## 通过标准与边界

- 候选由本地目录检索返回，型号匹配；模型不能自造零件号。
- 明确标注演示资料和适用性待确认。
- 模拟目录不能用于真实数据源的推荐。
- 不将两个告警记录说成两次已证实的部件损坏。
- 不声称已证明故障预测准确率、剩余寿命或采购适用性。

自动化验证：`python -m pytest tests/test_parts_demo.py tests/test_parts_catalog.py -q`。该测试验证数据隔离与候选匹配；本地模型的自然语言输出仍需独立复核。
