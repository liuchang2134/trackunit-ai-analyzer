# 指标不可计算原因与中英文复核

`assess_history` 新增 `valid_counter_sample_counts` 与 `metric_unavailable_reasons`，分别报告有效工时/怠速计数时点数量，以及三个窗口指标不可用的计算原因。没有有效运行区间时，`idle_counter_coverage` 返回 `no_valid_operating_intervals`，不再笼统归为怠速缺失或无效。

单条有效工时和怠速记录缺少第二个时间点，不能求增量；两条记录有计数重置属于区间不一致；有效工时增量小于 0.5 小时时仍可报告增量，但怠速比例不计算。0.5 小时是当前计算策略，不是厂家故障阈值，也不要求覆盖完整作业周期。数值算法未更改。

新增回归测试覆盖单条数据、计数重置和低运行时长，原有有效比例案例同时断言不可用原因列表为空。完整测试结果：167 passed，6 个已有弃用警告。

本地 qwen3:8b 实测：

- 中文单采样点，结果文件 `local-assistant-20260914T055334Z.json`：说明仅一条记录，不能计算窗口增量，未再断言怠速数据缺失。
- 英文单采样点，结果文件 `local-assistant-20260914T055416Z.json`：准确说明只有一个工时与一个怠速计数时点，不能求增量或比例；未推断设备运行质量。
- 同次英文错误型号案例没有输出错误备件候选，但摘要仍未明确机型过滤原因，使用了 two instances 这样的模糊措辞，并在摘要重复检查建议。结构检查通过不等于自然语言质量全部通过。

评价脚本新增 `--language zh|en`，英文请求和结构化检查文本均按英文运行，原始结果保留 language、请求、输入、证据及模型输出。每例只执行一次，不代表稳定性或实机诊断准确率。此前发布 ZIP 不含本次源码更新，后续重新打包时需再次验证。
