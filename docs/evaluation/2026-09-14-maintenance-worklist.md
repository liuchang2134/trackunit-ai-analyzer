## 业务与交互核验

1. **待处理入口通过。** 页面默认进入工作台，任务列表区分进行中/已归档；设备记录单独按已载入的未解决或冲突状态列出，带来源与版本。真实来源筛选实际返回 0 个待核对版本，并明确不代表设备均正常。

![刷新后工作台](ux-20260914/maintenance-worklist/02-worklist-restored.jpg)

2. **创建、检查、待补充及刷新恢复通过。** 从 SIM-PARTS-REPLAY-001 进入设备，建立“模拟演示：增压信号排查”，依次追加模拟检查和待补充说明。刷新页面后从“继续处理”读回同一任务及全部已保存原文。

3. **设备隔离与返回恢复通过。** 最初从任务列表打开后，设备入口没有共用同一条临时输入状态，导致未保存文字丢失。已修复任务 ID 与设备版本的关联，并增加 Node 回归用例。实际复测：切到 SIM-CW 任务输入为空，回到 SIM-PARTS 后恢复“尚未保存的模拟补充：需要核对线束。”。

![返回同一设备恢复输入](ux-20260914/maintenance-worklist/03-device-return-retains-note.jpg)

4. **归档与重新打开通过。** 写入归档原因后进行中列表为空，已归档列表显示该任务；设备原始待核对记录仍为 3 个版本。随后补充理由重新设为待补充，历史从 4 条增至 5 条，前四条逐字段比较完全不变。任务归档不等于机器故障解决。

![归档列表](ux-20260914/maintenance-worklist/04-archived-list.jpg)

5. **导出内容通过。** 浏览器点击过导出链接；本轮未找到浏览器最终落盘文件，因此不声称完成下载目录验收。实际读取同一附件接口，核对归档时四条完整原文、设备版本、状态和未验证标识，并保存 [归档时导出示例](2026-09-14-maintenance-case-demo-export.md)。1947 字节，SHA-256 `6a299341539b6f3ed92453c5742d6b946f750e45070756b2f2ed5539a6103296`。此示例是重开前的归档快照，当前任务已有第五条记录。

6. **设备证据与 AI 提交前交接通过。** 最初弹窗关闭事件会抢回焦点，已修复为关闭完成后再聚焦目标。实际最终证据跳转焦点为 overview-title，AI 跳转焦点为 question。人工问题和原有观察原样保留，再追加最近三条有文字的已保存记录；草稿保存按钮随之可用。没有点击开始分析，没有生成 Gemini 报告。
