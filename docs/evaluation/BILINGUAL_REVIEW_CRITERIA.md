# 中英文固定案例人工复核标准

范围：同一代码和本地模型下，各运行 matching_catalog、wrong_model、empty_catalog、one_sample、comprehensive 五例。中文和英文请求分别执行，输入为人工模拟数据，每例一次。此规模仅验证固定工作流，不支持实机准确率、语言优劣或稳定性比较。

程序检查覆盖必需工具、引用存在、原文检查步骤、候选集合，以及故障时点或缺失指标。另按以下标准逐例人工检查最终摘要，并查看工具证据：

1. 来源：明确为模拟片段，不将其描述成当前物理设备状态。
2. 时间和指标：不把首末事件的 25 分钟间隔说成复发周期；不捏造回放时刻与采样时间相同；单采样例不得把存在的怠速样本说成没有怠速数据。
3. 备件：匹配例只能给出候选，型号匹配不等于序列号或整机配置已经验证；错误型号与空目录例应陈述工具给出的确定原因，不添加无依据的推测。
4. 诊断：不能从运行状态、无记录或无规则发现推导健康；不确认根因、剩余寿命或直接更换。
5. 语言与操作：摘要使用请求语言；检查建议取自引用原文。中文目录原文在英文报告中保留不算擅自翻译成功，需单独记录这种混合语言限制。
6. 可读性：摘要解释观测及限制，避免重复整套检查列表。重复建议作为可用性问题记录，不与虚构事实混为同一严重度。
7. 文档与事件归属：人工目录不能称为已读取的维修手册；要求按手册检查不表示已取得手册。多条告警记录不能直接写成多次独立物理故障。综合查询应解释已计算的关键指标及覆盖范围，不能只说已经查询。

只有直接观察到满足才标通过。缺失关键说明记为不足，错误记为失败；不因结构通过推断语义通过。案例输入、代码哈希、模型标识、每步决策和最终输出应保留在对应 JSON 中。
