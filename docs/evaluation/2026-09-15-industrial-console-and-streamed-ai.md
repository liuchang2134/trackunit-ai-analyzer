# 验收记录：暗色工业风界面与流式 AI（2026-09-15）

本轮构建 `20260915.11-industrial-console`，插件源码 `0.7.0`。工作预览：<http://127.0.0.1:8890/assistant-ui/>。脱敏证据见 `2026-09-15-industrial-console-and-streamed-ai.json`。

本页只记录本轮实际做过的事，明确区分**已验证**、**未验证**和**外部接口限制**。自动测试数量不作为业务完成度证明。

## 一、本轮改动

1. **设备关联**：修掉"网页要求面板先确认设备编号，才肯显示本地已有数据的设备"这一死锁。真机数据已在本机时，不再等待握手，界面直接按当前 UUID 显示该设备；需要远程读取时才等待握手。另修：面板此前丢弃过一次编号提示后，同一页面内不会再问，重试按钮点了也没有反应。
2. **AEMP 车队检索**：只搜前 3 页却把结果说成"请稍后重试"，而重复读取必然同样失败。现在触顶返回可区分的状态与"已查 N 页 / 共 M 页"，界面不再承诺重试，也不再显示必然失败的重试按钮。同时，设备编号提示只要不可用（含 401/403，不再仅限 404），仍会继续走车队检索，而不是整次导入作废。
3. **界面**：网页端与插件外壳改为同一套深石墨 + 徐工蓝 + 青色状态线的工业风；设备概况改为紧凑参数网格放在首屏；图表坐标轴、提示框与缩放滑块改为深色可读；`prefers-reduced-motion` 仍可关闭状态点呼吸动画。
4. **流式 AI**：新增 `POST /assistant/investigate/stream`，一个请求即承载整次排查的事件流，按真实阶段推送（准备 / 读取设备快照 / 读取故障事件 / 计算工时与数据质量 / 第 N 次模型决策 / 整理报告）。只有通过校验的完整报告才会作为结果下发，局部模型输出不会渲染成诊断。
5. **停止与重试**：停止会中断该请求，服务端据此取消调查，不再发起后续模型调用；重试先中止仍在运行的请求再重新开始，避免两份结果混在一起。切换设备或离开页面同样会中止，旧设备的迟到事件不会落到当前设备。**本次不新增**单独按 id 撤销的接口——最初的设计把调查状态放在单进程内存里，两次请求可能落在不同工作进程上，实测会 404，因此改为一个请求自带整条流。
6. **启动器修复（顺带）**：`start_local.cmd` 在本机完全无法启动——它探测空闲端口时把"连接超时"当成"无法确认"，直接放弃启动。现在超时按"无监听"处理，并同时探测 IPv4/IPv6。
7. **样式表解析修复（本轮自查发现）**：`style.css` 里内层 `@media(max-width:340px)` 嵌套在外层 `@media(max-width:400px)` 内且少一个闭合括号，浏览器从该处起丢弃整个文件后半段——包括深色兼容层和新的流式进度样式。表现是网页上仍有两处浅色块（`ul.evidence-notes`、`#overview-export`）且停止/重试面板没有样式。已把内层媒体查询改为并列规则；解析规则数从 499 恢复到 622，浅色残留归零。**这条只靠自动化测试不会暴露，是靠实际渲染扫描发现的。**

## 四、外部接口限制（如实记录）

- 本机 `GET /api/asset/v2/assets/{uuid}` 仍返回 401，唯一可用路径是 AEMP 车队检索；该检索每次最多查 3 页（约 300 台），真实车队页数远大于此。**落在检索范围之外的设备读不到时，界面现在说明"未覆盖全车队"，但仍无法读到**——这是覆盖能力限制，不是本轮已解决的问题。
- 一个已经发出并正在传输的 provider 请求仍会在服务端完成；取消阻止的是后续模型调用。界面按此表述，不声称在上游中断了单次请求。
- 本机曾有两个 Python 进程同时监听 8890（一个来自其他运行时），会造成请求落到不同进程、行为不一致。本轮已清理，只保留项目 `.tmp/venv` 启动的单个实例。

# 追加：侧栏改版与 AI 引导的图册流程（构建 `20260915.12-ai-guided-catalog`，插件 `0.8.0`）

反馈是：侧栏"很不简洁现代"，并且"XGSS 的使用方法怎么体现 AI 在里面的作用"，"不能直接跳转网页这样展示"。本轮针对这两点改造。

## 六、原来的问题

XGSS 环节的实际流程是：点按钮 → 弹框加载官方页面 → 用户自己翻图册 → 点"读取" → AI 才从已读条目里挑候选。**AI 的作用全部发生在最后一步**，用户前几步看到的只是"它帮我打开了一个网页"，所以感觉不到 AI 参与。

## 七、改成什么样

把 AI 提前到"引导"位置，并让它在 XGSS 页面上留下可见痕迹：

| 步骤 | 谁在做 | 用户看到什么 |
|---|---|---|
| 1 | AI 依据故障码与手册推断可疑部件，并给出在图册里该找的检索词 | 侧栏列出可疑部件、判断依据、一列检索词标签 |
| 2 | 图册打开后，扩展在页面上把这些检索词标出（青色左标 + 深青底） | 不必盲翻，直接看到 AI 指向哪几行；本页未出现的词会明确列出 |
| 3 | 读回真实条目后，AI 结合真实料号给出候选与依据 | 候选来自实际读到的条目，不是猜的料号 |

侧栏外壳同时重做：品牌条 + 单行操作栏 + 可折叠详情层，去掉原来堆叠的多行工具条；图册与设置面板改为整宽浮层，长文本不再被挤在窄列里。

## 八、本轮修掉的三个实际缺陷

1. **浮层被 iframe 盖住**：操作栏的 `z-index` 低于工作区，图册/设置面板在 iframe 加载内容后完全不可见（此前 iframe 空白才碰巧可见）。已显式分层。
2. **浮层宽度依赖触发按钮**：面板用 `absolute + left/right:0`，包含块是触发按钮本身，被压到 72px 宽、文字挤成一条。改为相对侧栏定位的整宽浮层，偏移由脚本按操作栏实际底部设置。
3. **重复请求 AI 建议**：点"标出目标"会再次请求同一份建议并重复等待。改为复用面板上已显示的建议，仅在为空时才重新请求。

## 九、本轮验证与未验证

**已验证**：全量回归 Python **676 通过**、Node **164 通过**。新增用例覆盖：建议透传与展示、无报告时的明确提示、只把 AI 给出的检索词交给页面、非 XGSS 页面不注入任何脚本、标注结果回显；标注逻辑另有匹配/清除/幂等与越界拒绝用例。侧栏外壳用临时预览在本机 headless Chrome 390 像素下逐轮截图核对，最终确认 AI 引导块、检索词标签、可疑部件、三步说明与两个按钮完整显示；布局探针显示侧栏与浮层横向溢出均为 0、浮层内部无裁切元素。

**未验证（重要）**：
- **没有在真实 Chrome 中加载 0.8.0 操作侧栏**。上述侧栏截图来自镜像 `panel.html` 标记的临时预览文件，只证明 CSS 与版式，不证明扩展消息链路。`chrome_installation_verified` 保持 `false`。
- **没有在真实 XGSS 页面上实测标注**。标注只经过单元测试与假 DOM 验证；真实 XGSS 的表格结构、Element UI 行与跨域注入在真实浏览器中的表现尚未验证。

- 平台侧无法改动；扩展的标注由用户自己触发，只加视觉标记，不改页面内容。

# 追加：窄侧栏可用性修复（构建 `20260915.13-narrow-layout`，插件 `0.8.1`）

用户用实际截图指出："这玩意是给人看的吗？"——截图显示操作栏按钮文字被裁掉、外/内/XGSS 三层滚动条叠在一起。这是上一轮的真实缺陷，不是主观评价问题。

- **窄屏不再内嵌官方图册**：视口宽度不足 760px 时，对话框只取回官方地址并给出"在新标签页打开图册"这一个动作，不再渲染整站；宽屏独立网页端保留内嵌视图（那里宽度够）。

- **面板打开时点其他操作自动收起**，避免浮层盖住用户下一步要点的按钮。

# 追加：折叠面板的渲染缺陷（插件 `0.9.1`）

核对上一轮目标时，把 `panel.html` **逐字**复制成预览（不再手写镜像，避免标记漂移）后测得一个真缺陷：

**`position:fixed` 的详情面板脱离了 `details` 的隐藏规则。** `details.sheet` 的 `open=false` 时，面板的计算样式仍是 `display:block`、尺寸 `28×532`——折叠状态下面板并没有消失，只是被工作区盖住了。这正是"多层滚动条"的一个隐藏来源。

修法：`details` 收起时同步给面板加 `hidden`（`[hidden]{display:none!important}` 能压过 `position:fixed`）。修后实测折叠面板 `display:none`、尺寸 `0×0`；展开时满宽（390px 视口下面板宽 390）、内部无裁切元素。

## 本轮验证证据

把 `panel.html` 逐字复制成预览并在 **360 / 390 / 480** 三档实测：

| 宽度 | 操作栏 | 折叠面板 | 文档溢出 | 脚本错误 |
|---|---|---|---|---|
| 360 | 4 项各 90px，`clipped:false` | 全部 `display:none` | 0 | 0 |
| 390 | 4 项各 98px，`clipped:false` | 全部 `display:none` | 0 | 0 |
| 480 | 4 项各 120px，`clipped:false` | 全部 `display:none` | 0 | 0 |
