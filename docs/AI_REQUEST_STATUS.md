# AI 排查状态与故障交接

本功能首次验收于 2026-09-14 的 `20260914.11-ai-request-status` 构建。以下测试数量和联调记录属于当时版本；当前进度以源码中的 `docs/PROJECT_ACCEPTANCE_STATUS.md` 为准。

排查表单上方显示最近一次完整排查的结果、记录时间和失败类别。它帮助使用者在提交前了解已有证据；已配置密钥或曾经成功都不等于接口当前可用。“更新状态”只读取本机记录，不调用 Gemini，也不重新同步车联网数据。

## 记录规则

- 完整排查通过既有校验并写入历史后，记录“报告已保存”。分析成功但历史写入失败时，单独记录“报告未保存”，页面仍可使用本次结果。
- 失败记录仅保留规定的类别及可识别的额度窗口、计量单位和数值上限。不保存错误原文、问题、设备数据或凭据。无效设备或用户输入不替换上次模型请求状态。
- 文件位于被 Git 忽略的 `data/local/ai-request-status.json`，采用有界结构和原子替换。状态文件写入失败不改变报告结果。测试使用临时目录，不写用户记录。
- 新记录通过私有摘要关联提供方、模型、端点及密钥配置。摘要不在接口中返回；配置变化时旧结果不作为新配置的状态。当前部署为单进程，本机锁不代表多进程写入支持。
- `GET /assistant/ai-status` 返回 `Cache-Control: no-store`，始终标明 `is_live_check: false` 和当前可用性未核验。无记录、损坏、读取失败、未来时间均不会显示为健康；超过 24 小时会提示旧记录。
- 状态在设备切换后保留；收到本次排查响应后更新。较早的状态读取不能覆盖较新的排查响应。等待时间和状态刷新都不构成额度恢复证据。

## 故障资料到排查

“带此故障码进入 AI 排查”紧随故障状态。记录数量、截止时间及来源进入可展开的原文区；候选适用范围与出处仍直接可见。当时 XGSS 尚未接通，页面保留了该状态提示及可展开的参数细节；后续接口进度以当前验收状态为准。

点击交接按钮会带入准确故障码、选择故障与备件任务并聚焦问题框，同时将状态提示滚动到可见区域。仍需用户点击“开始分析”才发送请求。分析期间交接按钮禁用，关闭故障资料后焦点返回原“查看资料”按钮。
