# 机联智检

辅助已有车联网平台处理设备故障的工具，交付为网页工作区和 Chrome 侧栏插件。业务主线是 **Trackunit 故障事件 → 同机 XGSS 资料 → AI 维修与备件建议 → 邮件通知人员准备**；另一条核心目标是根据同机工况预测故障风险与时间窗口。AI 默认使用 DeepSeek API，设备资料与结果保存在本机，必要证据经过筛选后交给模型。

**当前版本（2026-09-22）：**构建 `20260922.2-fault-parts-email`，插件源码及已校验安装包 `0.9.11`。默认界面已收敛为“故障处理”和“风险预警”，使用一套“分析故障”操作。Chrome 网页已验证故障失败状态、既有图册结果与邮件预览；0.9.11 实装及原生侧栏全流程仍待验收。

**当前尚未完成端到端生产验收：**本日 Trackunit 故障事件复核仍为 HTTP 401；邮件预览和显式 SMTP 发送已实现，但尚未配置、未实发；实车预测数据不足。产品目标与完成标准以 [产品主线](docs/PRODUCT_SCOPE.md) 为准，执行状态见 [交接文档](docs/交接文档.md)。

## 比赛展示界面

网页与侧栏采用同一套深石墨工业风、徐工蓝按钮和紧凑设备信息。正常操作围绕当前机器和一条故障展开：选择已保存事件，按需补充现象，点击“分析故障”，查看可能原因、检查建议、真实备件候选与图示，再预览备件准备邮件。

“风险预警”目前展示数据缺口和进入故障处理的入口，没有可交付的实车故障日期或风险百分比。旧五任务选择、自由聊天、CAN 回放、历史案例、反馈任务、草稿和导出不再出现在默认业务界面；代码保留作兼容或维护用途。来源、模拟标记、接口失败和待核实条件仍保留，避免把演示结果当成实际诊断。

## 当前设备自动关联

工作预览在 [8890 故障处理](http://127.0.0.1:8890/assistant-ui/)。升级插件后需在 Chrome 扩展管理页重新加载，再重新打开侧栏；侧栏的“重新连接”只连接服务，不更新插件代码。

插件跟随当前 Trackunit 详情页的设备 UUID，并提取标签页标题中显示的设备编号作为查询提示。网页优先载入该机已有实测数据——此时**不等待**面板确认编号，真机数据在本机就直接按当前 UUID 显示；只有需要远程读取时才等待该确认。没有本地版本时，优先用编号查询 AEMP 单机快照，并要求返回的 `metadata.assetId` 与页面 UUID 完全一致；该编号不可用时（含 401/403）仍继续走车队检索，不会整次作废。没有提示时尝试 Assets 接口及最多 3 页的 AEMP 车队快照；触及页数上限时显示"已查 N 页 / 共 M 页"，不提示重试，因为重复读取会得到同样结果。只独立保存目标设备，不覆盖整队缓存；身份冲突、缺少有效采样时间或访问失败时显示原因。本次自动读取不调用 AI 或故障事件接口。

## 故障分析与资料来源

页面读取已保存的本机故障状态，不在每次打开时调用 Trackunit。“重新读取故障”是显式刷新补救入口。官方事件适配使用 Asset Event v3 的 `POST /asset-event/log`，只查询一个已登记设备，保留原始代码、SPN/FMI、来源标识、发生和解除时间。全局限频为 30 分钟最多 2 次故障请求，分页与失败均计数；未查询、接口失败、部分结果和查询窗口为空分别显示。

“分析故障”接续同一设备、同一事件背景，完成 AI 部件方向、XGSS 资料收集和有依据的维修与备件建议。首次 XGSS 页面提取仍依赖已连接的插件采集桥；单独打开网页并不代表已取得图册。料号和图片只能来自实际读取的同 VIN 资料，AI 负责关联和排序，不能生成不存在的订购号。只有 SPN/FMI 时不猜测转换成 OEM 故障码。

切换设备或停止分析时取消当前页面操作，旧响应不得回填新设备；已经发送到模型提供方的单次请求不保证立即中断。旧 `POST /assistant/investigate/stream` 等接口保留兼容，不作为另一套默认业务入口。初次采集、真实事件触发和通知串联仍需按 [产品主线](docs/PRODUCT_SCOPE.md) 验收。

## XE55U 测试案例与使用边界

首个故障联调案例采用 **XE55U 柴油液压挖掘机**和 **E4030 J1939 总线通信故障**。当前设备已有导入的 Trackunit 历史工时；E4030 单独标记为测试输入，不写入或伪装成真实 Trackunit 故障事件。预测主线则按产品范围限定为 XC948U 冷却系统，二者不混用验证结论。

1. 在 Trackunit 打开 XE55U，打开助手侧栏并核对当前设备；网页也可从“查找设备”选择已载入设备。
2. 在“故障处理”查看故障接口状态。有真实事件时选择该事件；本机目前显示 401，不能把空列表解释为无故障。
3. 需要联调 E4030 时，在“人工补充故障码与适用配置”核对适用配置及测试来源，保留模拟标记；它不写入真实 Trackunit 事件列表。
4. 在同一表单点击“分析故障”。后续资料检索与分析沿用本次背景；不再通过旧“读回图册条目 → 结合图册继续分析”入口另开一轮。
5. 有有效建议后查看依据、图示和待确认条件，再点“备件准备邮件”预览。发信渠道与收件人未配置时不能发送；配置后仍需显式点击发送。

本机手册知识仅为已核查的 **XE55U.00III / EWMEN55U-A02 / PDF 第 286–287 页**摘录，保存在私有目录；并非整本手册或所有配置已导入。此前 E4030 测试验证了手册辅助推断的软件流程，不能证明实车故障或诊断准确率。

**XE55U 真实料号闭环尚未完成：**此前该 VIN 的 XGSS 请求虽为 HTTP 200，业务响应却为 `success=false`、VIN 不存在，未取得对应零件条目。本日成功读取工时也不能补足 XGSS 适用资料或故障事件授权。

## 启动

Windows，使用 Python 3.12，在项目根目录的 CMD 运行。首次克隆：

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-xgss.txt
copy .env.example .env
start_local.cmd --port 8890
```

已有环境直接运行 `start_local.cmd --port 8890`。本机检查用 `start_local.cmd --port 8890 --check-only`；不会停止或重启已有进程。查看已载入设备资料无需填写模型密钥；真实 AI 分析需要在 `.env` 配置 `DEEPSEEK_API_KEY`。默认 `AI_PROVIDER=deepseek`、`DEEPSEEK_MODEL=deepseek-flash`，只连接 DeepSeek 官方地址。修改配置后重启后端；网页和插件共用后端密钥，无需分别填写。

网页入口：[故障处理](http://127.0.0.1:8890/assistant-ui/)。Chrome 插件直接加载项目中的 `extension` 文件夹，连接设置选择 8890，详见 [插件说明](extension/README.md)。不需要单独编译当前网页和插件。

邮件发送在后端配置 `RESEARCH_EMAIL_SMTP_HOST`、`RESEARCH_EMAIL_SMTP_PORT`、`RESEARCH_EMAIL_SMTP_SECURITY`（`starttls` 或 `ssl`）、`RESEARCH_EMAIL_SMTP_USERNAME`、`RESEARCH_EMAIL_SMTP_PASSWORD`、`RESEARCH_EMAIL_FROM` 和 `RESEARCH_EMAIL_TO`。凭据只放本机配置，不进入网页、插件或 Git。当前未配置、未实发；服务器接受邮件与收件人实际收到是不同的验收结果。

只有图册、没有适用维修手册时，结果给出 AI 检查方向，不能标成原厂拆装步骤或编造维修参数。TV12U / 260224 和 XE55U 私有参考资料作为人工补充依据保留，完整内部原表与提取文件不随 Git 分发。

已安装旧版插件时，需要在 Chrome 扩展页重新加载项目的 `extension` 文件夹。侧栏默认优先连接 8890（可在设置中改为 8892）；仅重新连接网页不能更新扩展脚本。重新连接会重新载入工作区，未保存的输入将丢失。自动跟随会为没有本地数据的设备发起有界只读请求，不自动调用 AI；XGSS 提取由用户启动，来源只代表已读取页面的覆盖范围。

## 复核 AI 的依据（可重复运行）

AI 的引用是否真的指向已读取的证据，可以自己跑一遍核对；脚本只读本机记录、不调用模型：

```bat
.tmp\venv\Scripts\python.exe scripts\evaluate_ai_grounding.py
```

它在 `docs/evaluation/` 写出 JSON 与 Markdown：扫描多少条记录、其中多少条真的跑过模型、共核对多少条引用、有多少条悬空，并附每条运行的明细与所用代码的哈希。**这里度量的是引用能否对上证据，不是诊断正确率**；准确率需要带标签的验证集，本机没有，因此不作声明。
