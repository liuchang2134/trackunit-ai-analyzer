## 面向既有车联网平台的工程机械 AI 排查与备件辅助工具

### 项目摘要

机联智检面向制造商、经销商技术支持人员与现场服务工程师，为已有车联网平台增加设备排查辅助能力。项目将设备运行记录、故障事件、现场观察和备件资料放入同一工作流程，帮助使用者判断证据是否充分、确定下一步检查事项，并核查候选备件的适用范围。既有平台继续承担设备管理与遥测采集，辅助工具负责证据整理、分析解释和检查记录。

当前方案采用 Gemini API 进行语言理解、工具选择和报告生成，本机运行网页、FastAPI 后端、数据处理、资料检索与历史记录。主要产品形态是网页工作区和 Chrome/Edge 侧栏插件。第一阶段围绕柴油液压挖掘机，包含挖掘、回转、卸料、怠速、行走及停机的模拟数据和工况识别演示。

现已具备部分真实数据导入、设备趋势图、异常证据查看、本地备件目录匹配、模拟工况回放和绘图数据下载。完整 Gemini 排查尚未验收，XGSS 官方手册与正式备件目录仍待联调。项目申请以可复现原型参加评审，寻求授权数据、维修资料和工程人员复核支持；不将模拟结果作为实机故障预测能力或商业收益证明。

## 一 问题与用户任务

车联网数据需要结合采样时间、设备状态和维修资料解释。工时不变可能来自停机、通信中断或缓存陈旧；重复故障记录可能属于同一次持续异常。故障码只能提供检查方向，同名零件也可能因机型、序列号或配置不同而不适用。技术支持人员需要反复查证这些关系，单纯展示仪表盘或生成通用文字不能完成该任务。

项目首先服务远程初筛、维修前准备、历史案例复盘和培训演示。预期价值是减少资料检索和证据整理时间，减少未经核查的换件建议。节约时间、误报和遗漏的改善幅度，将在限定设备与固定任务的对照试用中测量，不预先填写未经验证的节油或停机减少比例。

## 二 产品形态与操作流程

用户在 Trackunit 设备详情页打开侧栏，主动读取当前设备 ID，再核对本地数据对应的机型、序列号、来源和数据版本；也可直接使用完整网页。一次排查按以下步骤进行：

1. 查看所选设备的运行趋势、记录时段、缺失信息和未解决故障。
2. 点选故障查看原始事件、本地目录候选和资料出处，需要时带入 AI 排查。
3. 选择排查任务，补充现场观察；点击开始后，由后端向 Gemini 发送所选证据。
4. 核对建议检查、引用依据及备件适用限制，记录实际检查结果并继续排查。
5. 导出报告和数据，保留输入来源、资料版本及前后报告关联。

### 设备工作区

界面以设备及故障任务组织。设备选择、数据来源与时间在前，趋势图和故障记录紧随其后，AI 是工作区内的操作。用户可切换指标、选择时间范围、缩放曲线或查看表格；缺失值留空，整体工时统计保持原有计算范围。数据表限定高度并支持键盘滚动，绘图 CSV 保留设备、版本、来源、时间和单位。

点选故障后，用户可先直接阅读已有资料，不必等待模型响应。进入 AI 排查会填入故障码和任务，仍需主动提交。切换设备或数据版本时，问题与观察草稿相互隔离；返回原设备可恢复其内存草稿，刷新页面则清空。模型失败时保留输入并恢复控件，说明本次没有生成报告。页面明确显示模拟来源、历史状态、目录不足和手册尚未接通。

### AI 备件映射与手册

Gemini 根据故障及观察选择查询方向；程序按机型、序列号限制、故障码或部件类别筛选本地目录。候选包括零件号、名称、匹配依据、原文检查、文档出处、页码和版本。未提供序列号适用范围时，只能说明机型匹配；演示零件号以 DEMO 开头，不混入实测设备推荐。

XGSS 已提供认证跳转接口说明和 RSA 公钥，接口方说明可增加故障码返回排查手册网址。本地加密适配已有测试；获准使用的身份、故障码字段及位置、type 与业务编号规则尚待确认。下一步将验证具体设备和故障码能否打开正确手册。现有跳转接口不能证明已取得手册正文、BOM、库存、价格或正式备件搜索能力，这些能力需单独确认接口和授权。

### 故障预测的交付边界

当前功能提供异常线索和风险筛查，尚未交付经验证的部件故障预测、失效概率或剩余寿命。后续以有维修标签的单一故障类型为起点，记录失效发生时间、负荷、传感器和维修结果，评估预警提前量、误报、漏报及跨设备效果。模拟注入告警用于展示软件流程，不能替代真实失效样本。

## 四 技术架构与数据方案

### 数据与证据处理

Trackunit 授权 API 和用户导入的 JSON/CSV 进入本机数据层。每个导入数据集保留内容版本和来源，不用模拟记录填补实测缺失。处理过程检查时间、设备归属、数值范围、重复与冲突；只对通过校验的区间计算工时增量和怠速占比。有效区间合计不等于完整窗口总量，空故障响应也不等于设备没有故障。

备件资料以本地结构化目录保存，保留适用条件和原文出处。设备趋势、故障资料和目录精确查询可独立于 Gemini 使用。图表采用本地打包的 Apache ECharts，下载时核对图表内容版本，防止设备数据更新后悄然导出不同内容。

### Gemini 与本机算法的分工

本机负责确定性计算、证据编号、适用性过滤和保存记录；Gemini 负责理解问题、选择允许的工具和组织解释。明确任务先读取必要快照、故障和趋势，模型仍负责补充查询方向与最终解释。建议检查通过已有步骤编号返回对应原文，程序检查引用与候选范围，并要求修正已知的无依据数值和时间表述。有限校验仍不能保证所有结论正确，最终由服务人员复核。

模型不执行任意代码，不访问任意地址，不直接控制设备或采购备件。当前采用官方 Gemini API，密钥留在本机后端；提交分析会将选定证据、问题和检查反馈发送到 Google。云端处理需取得业务数据使用授权，并根据部署单位要求核查服务条款和数据范围。网页与数据仍在本机，完整 AI 推理需要联网。

当前模型别名为 gemini-flash-latest。整个排查设置 120 秒时限，单次模型决策遇明确临时服务器错误最多尝试 3 次；429 额度限制不自动重试。每日额度、每分钟限额和未知错误分别解释，云端失败不伪造报告，也不自动切换模型或付费方案。

### 挖掘机模拟数据

模拟器以柴油液压挖掘机的工作循环生成挖掘、载重回转、卸料、回程回转、怠速、行走和停机轨迹。采用假设的循环时长、负荷与操作差异，保持燃油消耗累计、工时累计和液压功率关系的一致性；温度采用随负荷变化的一阶响应。型号资料仅作为参数范围参考，尚未校准为真实设备数字孪生。

数据分为高频物理通道、加入噪声的模拟传感器观测和车联网可见记录。分别模拟正常停机、通信中断、终端掉电、燃油信号冻结、缓存陈旧和批量延迟。详细转速、压力、流量和速度仅在模拟侧提供，不宣称当前 Trackunit 账户已具备这些字段。未来真值与标签只用于评测，不进入模型决策输入。

### 工况识别模型

随机森林使用当前及过去采样点的转速、液压压力、液压流量和地面速度，输出六类工况或低得分未知。载重与回程回转合并为回转，预热归入怠速。模型与大语言模型独立运行；工况分类结果用于解释作业分布，不能直接当作故障预测结果。实测信号不足时，不输出假设的工况识别。

## 五 现有证据与评测设计

### 已取得的工程证据

真实数据方面，先前已完成 Trackunit 认证、设备快照及一台挖掘机的历史工时读取。当前导入包含 36 个时点，通过 20 个工时间隔合计 3.9 小时，另有 15 个区间未通过一致性检查；怠速记录缺失。该结果证明部分接入和区间统计可用，不证明故障数据或完整运行时段已覆盖。

模拟备件演示包含 105 个有效时点和两条重复未解决告警。实际网页已核对趋势切换、资料出处、机型不匹配、历史状态和草稿隔离；下载的末尾一小时 CSV 含 61 行。另一份实测怠速 CSV 含 36 行空值，验证缺失值没有被写为零。

2026年9月14日的最新完整 Gemini 请求使用模拟证据，Google 返回每日免费请求额度耗尽，返回的上限为 20 次。应用只尝试一次便结束，没有生成报告。此前还观察到服务繁忙错误。因此历史本地模型报告只能证明旧架构流程，不能用作当前 Gemini 成功验收。

### 工况模型的独立模拟测试

按完整独立班次划分 28 段训练、7 段验证和 7 段测试，测试包含 40,320 个模拟采样点；未随机拆散相邻行。0.65 得分阈值在查看测试结果前固定。

|指标|结果|解释|
|---|---|---|
|六类原始预测准确率|90.04%|模拟测试，不是实机准确率|
|宏平均 F1|0.9078|卸料与回转较易混淆|
|达到阈值的覆盖率|89.85%|其余样本保留未知|
|达到阈值样本准确率|93.48%|不能代替全样本指标|
|额外噪声下已分类准确率|84.11%|说明分布变化会明显降低效果|

模拟器中的怠速、停机和行走关系较简单，结果可能偏乐观。压力缺失的 8,064 个点全部返回未知；高得分也可能误判。模型得分未经真实概率校准，后续必须用实机标注数据检验。

### 软件与使用效果验收

当前 Python 测试 296 项、前端逻辑测试 18 项通过，覆盖数据隔离、异常输入、引用、备件适用范围、下载和错误处理。这些工程测试不等于诊断准确率。Gemini 完整验收还需固定案例实际生成报告、核对出处、保存检查反馈并完成续查。

使用效果拟比较同一任务下的人工阅读、规则摘要和 Gemini 辅助流程，记录任务完成时间、需修改结论、错误换件建议、引用正确性及未决问题。按设备或班次划分评测集，保留失败与拒答，不只展示成功案例。部件预测阶段另行评价预警提前量、误报、漏报和置信度校准；试用人员与真实维修数据尚未落实。

### 剩余工作顺序

第一步完成 Gemini 端到端验证。在当前模型额度恢复，或负责人确认其他可用模型后，使用固定模拟案例核对证据、报告、候选、保存和反馈续查。错误必须可定位，失败记录不得进入成功报告。模型可用额度与供应商响应时间不由开发方控制。

第二步核实 XGSS 请求契约与身份，联调一个明确机型和故障码的正确手册；取得正式备件资料后，验证机型、序列号及不适用场景。接口提供方未确认前，保留清晰的未接通状态。

第四步与工程人员开展限定设备、限定故障的试用。收集真实观察及维修结果，检验资料查找效率与结论可靠性；达到数据条件后开展部件预测。没有真实样本时，参赛演示采用明确标识的模拟案例，并说明现场效果尚未验证。

## 七 资源预算与商业验证

本期使用已有电脑、开发环境和已购会员，不新增现金开发预算。Gemini 使用现有 API 项目，当前按返回的免费额度安排验证；未经负责人确认不启用收费方案。已购开发会员不等于 Gemini API 无限额度。免费额度不足时，完整云端排查不可用，但本机趋势、故障资料和目录查询仍可使用。

零新增现金不代表零成本。开发时间、资料整理、专业人员复核、硬件和维护应进入后续核算。当前没有已确认客户、收入、订单或投资回报数据。初期通过制造商或经销商技术支持团队的小范围试用，测量整理资料和完成排查的时间、复核修改及适用性问题，再判断是否值得开展集成服务或年度维护。

未来收费方式可包括授权部署与集成、目录整理和维护服务。商业模型需核实资料权利、API 成本、使用频率、支持工作量与付费意愿，现阶段不预测未经调研的市场份额或盈利规模。最急需的支持是授权历史数据、正式维修及备件资料、接口方参数确认和工程师复核时间。

## 八 创新点与知识产权
