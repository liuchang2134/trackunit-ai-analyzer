# 机联智检项目计划书

## 面向既有车联网平台的本地 AI 诊断与备件辅助工具

AI＋工程机械专业赛｜参赛 Proposal 工作稿

版本：2026年9月14日。项目阶段：本地软件原型与模拟流程验证。开发资源：现有电脑与已购会员，零新增现金开发预算。

### 执行摘要

机联智检是一款运行在既有车联网平台旁的辅助工具。面向工程机械远程技术支持与现场服务人员，将设备遥测、故障事件、现场检查记录和本地备件目录组织成可追溯的分析流程，帮助使用者回答三个问题：当前数据能说明什么，下一步需要核实什么，哪些备件值得进一步检查适用性。

产品采用浏览器侧栏扩展配合本地服务。数据处理、目录检索和大模型推理运行于本机；真实设备数据通过授权 API 获取，模拟数据用于演示和开发。扩展已实现点击后从 Trackunit 设备详情网址读取设备 ID，并定位本地对应数据；多个历史版本需明确选择。网址与本地设备的对应关系已核实，实际安装后的侧栏联调仍待完成。

项目已实现本地模型调用证据工具、时间窗口工时分析、异常数据筛查、JSON/CSV 导入、备件候选检索及检查反馈留存。另已训练模拟挖掘机工况分类器，交付测试集回放页面。真实 Trackunit 快照和历史工时已读取成功，故障事件权限仍有缺口。当前成果证明原型链路与模拟基线可以运行，不证明实机故障预测准确率、维修收益或备件采购适用性。

## 一、问题与目标用户

车联网平台提供大量设备数据，但技术支持仍需要理解采样时间、判断数据是否可信、查阅对应机型资料，并与现场人员反复确认。工时不变既可能来自设备停机，也可能来自通信问题、数据延迟或缓存陈旧。故障码提供检查线索，但不能直接证明某个部件损坏；同名备件也不一定适用于当前整机配置。

目标用户包括工程机械制造商和经销商的技术支持人员、现场服务工程师以及车联网产品测试人员。典型任务是远程初筛、维修前准备、案例复盘和新人员培训。项目希望缩短资料查找和证据整理时间，减少缺乏依据的换件建议；具体改善幅度需通过对照试验验证。

第一阶段设备范围为柴油液压挖掘机，模拟工况包含挖掘、回转、卸料、怠速和行走。设备类型和信号可用性必须明确，不能将某一挖掘机的规律直接推广到全部工程机械。

## 二、产品形式与工作流程

交付形式为 Chrome/Edge 侧栏扩展、本地 FastAPI 服务、本地模型和资料目录。侧栏是主要入口，完整浏览器工作区用于较复杂的证据查看和备件表格对比。现有车联网平台继续承担原有设备管理功能。

一次使用流程如下：

1. 选择设备或已导入的数据集，查看来源与最后上报时间。
2. 输入分析问题，可补充已完成的现场检查及观察。
3. 本地 AI 选择快照、故障、趋势和备件工具，读取结果后形成建议。
4. 用户查看指标、AI 解释、带来源的检查步骤和备件候选，在诊断记录下保存检查结果，再带已保存反馈继续分析；新报告保留原记录关联。
5. 导出包含设备、数据来源、证据、工具记录及建议的报告，交由服务人员复核。

界面采用紧凑工作区：设备信息置顶，诊断任务与结果分栏，导入数据和备件库位于独立页面。接口核验表区分返回数据、空响应、无权读取和未核验，并说明其仅代表上次选定设备与时段。

### 故障预测的技术边界

项目将“故障预测”分阶段推进。当前阶段提供异常早期线索和检查优先级：发现数据陈旧、异常增量或重复未决告警后，提示需要核实的事项。它不是已校准的部件失效概率模型，也不输出预计损坏日期或剩余寿命。

后续需要真实维修结果、故障发生时刻、工况负荷及健康对照数据，才能建立并验证部件级预测模型。没有这些数据时，系统保留“证据不足”，不得以模拟准确率替代实机性能。

### AI 备件映射

本地目录保存零件号、名称、部件类别、适用机型、可选序列号清单、关联故障码、检查要求和文档出处。模型可以选择查询方向；实际候选由程序按机型、序列号限制及故障码或部件条件检索。

返回候选时显示匹配依据、来源页码和版本，并说明是否验证了序列号适用范围。仅匹配机型不能视作适配认证。第一版不支持复杂选装配置、序列号区间和替代件链；采购前须以制造商资料和实际整机配置确认。演示零件号以 DEMO- 开头，并禁止混入实测数据的推荐。

## 四、技术架构与 AI 的作用

数据层接收 Trackunit 授权快照与历史序列，以及用户导入的规范化 JSON/CSV。不同来源的数据独立保存，不用模拟记录填补真实数据缺失。

证据层执行时间和数值检查：保留合法零值，剔除冲突记录，识别不合理增量；工时和怠速采用各自可用的记录，只有时间对齐、覆盖足够时才计算占比。有效区间合计不等于完整窗口总量。记录缺失不能证明设备正常。

推理层使用 Ollama 本地模型，当前默认 qwen3:8b，采用量化权重。模型在有限步骤内选择预定义工具，不能执行任意代码、访问任意地址或控制设备。检查建议通过选择已有规则或目录中的步骤编号返回原文，保留出处。程序验证引用来源，并针对已知的无依据数值、时间换算和肯定健康结论要求模型重写。指标不可计算和备件未匹配的原因由程序提供。这些有限校验不能证明所有摘要正确，结果仍定位为辅助建议。

工况识别采用另一条可独立评测的机器学习路径：随机森林读取转速、液压压力、液压流量、地面速度以及当前和过去采样点的变化特征，输出六类工况或低得分未知。它与语言模型分工，不把语言模型自述当作分类结果，也不把工况识别等同于故障预测。当前详细传感器由模拟器生成，真实已接入信号不足以运行该分类器。

展示层是本地网页及侧栏扩展。密钥仅留在本地配置，不进入扩展文件或前端代码；助手推理限定本机地址，不提供云模型失败回退。首次安装依赖和模型需要网络。现已验证同机新虚拟环境安装、PowerShell 7 后端启动与重复启动，以及仅允许环回连接的 Python 进程内模拟诊断；后者未隔离浏览器和 Ollama，不等同于整机断网或模型冷启动验收。真实 API 同步仍需要网络。

项目的技术价值在于把模型的语言理解、工具选择与解释能力结合到工程数据约束和备件适用性检查中。模型负责组织问题与解释证据，程序负责计算、数据来源和候选检索。是否优于人工或规则基线，必须通过评测确认。

## 五、数据方案与现有验证

### 数据来源

- 授权接口数据：已验证设备快照和一台挖掘机的历史工时读取；原始响应保存在本地，不随公开参赛材料分发。
- 机制仿真数据：在假设的柴油液压挖掘机工况下生成运行轨迹，并模拟通信、供电、信号冻结和缓存等问题。用于可复现开发，尚未以真实设备测量标定。
- 人工流程案例：为备件演示注入告警，结合明确标注的演示目录。它证明软件如何组织检查流程，不证明真实失效机理。
- 用户资料：后续引入经授权的维修手册、备件目录和历史工单，并记录文档版本与适用范围。

### 已观察到的工程结果

本地模型已完成“读取故障—查询备件—读取快照—形成建议”的实际调用链，返回演示传感器候选及线束、接头、测量值检查要求。导入模拟工况可生成时间窗口工时与怠速分析，显示独立计算结果及来源。

真实历史接口返回过36条累计工时记录，但对应怠速序列为空，故障事件查询返回401。当前系统保留这些缺口。该批工时有部分相邻区间未通过一致性规则，报告只统计通过检查的区间，不据此声称全时段运行量。

实测还发现过模型自创怠速阈值和错误时间换算，已加入针对性校验并复测。这说明完整验证需要覆盖错误输出，而不能仅展示成功案例。当前自动化测试覆盖数据隔离、异常计数器、适用性匹配、引用验证、导入冲突和接口错误处理，不等同于实机诊断准确率。

### 本地 AI 与工况识别结果

在同一输入与程序版本下，对 qwen3:4b 和 qwen3:8b 各测试四个目录及数据边界案例，两者均通过工具和引用结构检查。8b 在这批案例中改善了单样本累计量解释，另两例补测通过；近期还完成英文单样本及错误型号补测，单样本可正确说明缺少第二个计数时点。摘要仍可能误述模拟时间关系、笼统解释过滤原因或重复建议；自动检查不能完全发现这些问题。案例量很小，不能据此声称普遍诊断优势。

工况模型按完整独立班次划分：28 段训练、7 段验证、7 段测试，测试共 40,320 个模拟采样点。输入不含工况标签、场景编号或未来数据。固定得分阈值为 0.65，结果如下。

|指标|独立模拟测试|解释|
|---|---|---|
|六类原始预测准确率|90.04%|包含低得分样本，非实机准确率|
|宏平均 F1|0.9078|各类别同等权重；卸料与回转较弱|
|达到得分阈值的覆盖率|89.85%|其余 10.15% 保留为未知|
|达到阈值样本的准确率|93.48%|仅针对已分类样本，不能替代全样本指标|
|额外噪声下已分类准确率|84.11%|压力测试结果；高分仍可能误判|

模拟器中的怠速、停机和行走关系较简单，结果可能偏乐观。压力缺失的 8,064 个点全部返回未知；压力冻结受影响区间的分类覆盖率降至 41.18%。这些失败和拒判结果随报告保留。模型得分是内部投票结果，未校准成真实正确概率。

## 六、评测与验收设计

|评测对象|方法|验收记录|
|---|---|---|
|数据处理|正常、缺失、重复、冲突、重置及乱序输入|逐案例输入、预期值、实际值与失败原因|
|AI 结论|同一证据集比较人工阅读、规则摘要和本地 AI|有依据结论比例、错误确定性表述、合理拒答情况|
|故障与备件|正确机型、错误机型、序列号不符、目录缺失及演示隔离|候选适用性、出处完整度、越界推荐次数|
|主动检查|固定可用证据及检查权限的场景对照|检查次数、无效检查、最终未决与正确结论|
|实际使用|限定设备与任务的服务人员试用|任务耗时、复核修改、遗漏问题和使用反馈|
|本地部署|冷启动、重复启动、模型缺失、断网及扩展侧栏|运行日志、失败提示、可复现步骤|

评测集应按设备或完整班次划分，避免把同一时序的相邻片段分散到训练与测试。评估用真值和决策时刻之后的信息不进入模型输入。不得只报告平均表现；应列出失败案例、样本规模、数据来源和适用边界。

预测模型阶段另需评估预警提前量、误报率、漏报率和置信度校准，并按机型与工况分层。当前不填写未经测量的准确率、节油比例或停机减少比例。

## 七、交付物与实施安排

参赛交付包应包括：

1. 侧栏扩展与本地服务源码、安装依赖清单及启动检查。
2. 本地模型配置和安装说明；模型按其许可证单独获取。
3. 可复现模拟数据生成器、演示数据集、数据字典及独立划分说明。
4. 工况训练脚本、数值模型、测试与压力测试报告、交互回放页面。
5. 带出处和适用范围的演示备件目录模板、JSON/CSV 导入说明。
6. 故障到备件及检查反馈演示脚本、典型导出报告和失败案例。
7. 本地模型对照评测、实际运行结果和已知限制报告。
8. 更新后的参赛计划书、答辩演示材料与演示视频。

当前已交付典型报告、10 页可编辑答辩稿、44 秒中文字幕模拟功能短片和本地原型包。短片包含实际界面定格与动态工况回放，等待过程经过剪辑，不作为耗时基准，也未展示侧栏安装或完整反馈操作。

主要待办是侧栏实际安装联调、完整离线冷启动、双语及语义错误评测、正式资料与实机验证，并持续更新最终交付包。同步界面成功路径、报告实际下载和后端启动已有直接验证，整套交付仍需逐项验收。

以竞赛项目提交时间为约束，按“可运行链路—数据与目录验证—部署及展示验收”安排剩余开发。若真实资料或权限无法及时取得，演示应使用标识清楚的模拟案例，并如实说明受限功能；不能以虚构案例补齐。

## 八、资源、商业路径与合作需求

本期使用已有电脑、开发环境和已购会员，新增现金开发预算为零，不新增云推理或服务器付费服务。零新增现金不代表没有成本：开发与审核时间、现有硬件、电力和后续维护均需计入未来项目核算。现阶段不存在已确认收入或量化投资回报。
