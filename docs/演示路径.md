# 演示路径

本次参赛展示：**当前设备 → 故障与运行数据 → AI 排查 → XGSS 资料提取 → 备件与维修建议**。网页与 Chrome 侧栏共用工作区，主导航为「设备排查」。

插件源码为 0.9.9，网页主逻辑、图册工作区与 XE55U 提示脚本标识为 `20260921-flow-1`，样式标识仍为 `20260921-diagrams-1`。当前展示范围及验证情况见[交接文档](交接文档.md)。

## 0. 启动与连接

已有服务时先检查：

```bat
start_local.cmd --port 8890 --check-only
```

需要启动服务时运行：

```bat
start_local.cmd --port 8890
```

打开[设备工作台](http://127.0.0.1:8890/assistant-ui/)。AI 分析使用后端已配置的 DeepSeek API，密钥不填入网页或插件。

Chrome 的 `chrome://extensions` 页面中，首次选择「加载已解压的扩展程序」并选中项目 `extension` 文件夹；已安装则点击扩展卡片的重载按钮，再打开助手侧栏。本次工具环境下，原生扩展管理页这一步只能手动操作。侧栏应显示读取设备、跟随、图册、设置和连接状态。

## 1. 关联 Trackunit 当前设备 [无需密钥]

在已登录的 Trackunit 设备详情页打开助手侧栏，检查机型、VIN/PIN 是否一致。必要时点击「读取设备」。

工作区显示机型、VIN/PIN、采样时间和数据来源。切换设备时应跟随更新；未关联成功时先处理页面提示，不进入后续分析。这里的“无需密钥”指无需 AI 密钥，远程设备读取仍需已配置的 Trackunit 凭据。

## 2. 查看故障与运行数据 [无需密钥]

在「运行数据与故障记录」查看已载入的工时、怠速、燃油和故障数据。采样不足、过期或故障记录为空时，以页面提示为准，不能据此判断机器当前健康。

有人工故障码时，在「故障码资料」查询适用资料并核对机型范围，确认后带入。没有真实故障码时可输入模拟现象，必须选择模拟来源，不能将其作为实车事件。

## 3. AI 辅助排查 [需密钥]

在「AI 辅助排查」选择任务，按需补充问题，点击「开始分析」。

查看诊断摘要、可疑部件、检查建议和资料依据。等待过程可使用「停止分析」。模型请求失败时显示失败原因；不能用空结果解释设备状态，也不能把界面连接成功当成 AI 分析成功。

## 4. 提取 XGSS 资料 [需密钥]

在「备件与维修建议」核对故障现象和来源，点击「查找备件与维修资料」。已有分析时，也可通过结果下方「继续查找备件」带入当前设备的部件检索词。

这一步需要在 Chrome 助手侧栏中操作。AI 给出检索方向后，插件在对应 VIN 的 XGSS 页面查找并提取图册条目或维修资料。若需要登录，完成登录后继续；没有提取到资料时明确显示资料缺口，不填写猜测的料号。

「更多操作与检索词」可查看和调整检索词、手动触发「查找并提取资料」以及「查看设备证据」。

## 5. 核对备件与维修建议

查看 AI 排序后的备件候选、名称、料号、推荐依据、更换条件及检查建议，展开来源核对实际图册行或手册摘录。

已采集图示的设备会显示“当前设备图册”；点缩略图可放大、缩小或适合窗口。备件候选只配对应来源页的图，并保留图中序号。当前 XC948U 已有冷却系统及散热器安装组件两张真实图示；图片不发送给 AI。

同 VIN 图册对应整机范围，但名称相似不等于确认损坏；还需核对组件配置和现场检查条件。仅有零件图册时，可展示 AI 检查建议，不能称为官方维修步骤。

## 已验证与待验证

- 已完成 XC948U 的设备快照、真实图册条目与 DeepSeek 联合分析验证；采用浏览器辅助采集，不能据此宣布插件自动采集全流程已通过。
- 用户已确认重载此前 0.9.8；当前 0.9.9 包实装、设备切换跟随、自动 XGSS 导航与图文提取仍需在真实 Chrome 侧栏核验。
- 样本量小，没证明诊断准确率或故障预测准确率；故障码是测试输入时应明确标记，模拟现象也不代表设备真实发生该故障。

仅做本机开发复核时，可运行 `scripts/evaluate_ai_grounding.py` 检查已保存输出的引用是否指向已有证据。这不在现场展示路线内，也不是诊断准确率验证。
