# 开发交接（公开版）

项目：**基于 Track Unit 平台的车联网 AI 备件和故障预测 Chrome 插件**。产品品牌为“机联智检”。运行与配置以 [README](../README.md) 为准，当前版本说明见 [RELEASE_0.9.31.md](RELEASE_0.9.31.md)。

此文档保留开发所需的功能、代码入口和验证边界。真实设备标识、客户采样、现场故障记录、研究记录链接及本机操作日志不随源码分发。XC948U 是选取的一台应用案例，不表示产品只面向该机型，也不表示其他机型已经逐一验证。

## 一、产品主线

- 首页保留当前与历史故障选择、基于故障的配件推荐、XGSS 原图和参考估价。
- “故障预测”为二级入口。用户读取 Advanced Sensors 连续数据后，AI 根据有效工况、变化趋势和故障背景提出风险假设；“潜在故障配件”在该风险卡内接续同设备 XGSS 查询。
- 故障配件与传感器风险查询独立保存；风险查询不能覆盖首页活动研究、故障输入、图片或估价。
- CAN 模拟回放、检查反馈任务、草稿与历史报告等旧代码保留，不重新放回当前主界面。

## 二、设备与故障来源

- Trackunit 设备 API、可见 Events 页面与 Advanced Sensors 导出分别保留来源和时间范围。
- 页面可见事件不是官方故障 API 的完整历史；故障 API 授权与 AEMP/传感器授权分别判断。空列表或授权失败不能解释为设备没有故障。
- 已解除历史故障单独生成复发时的条件性备件参考，不写成当前损坏。
- 身份以设备、VIN/PIN、数据版本共同校验；设备切换后的迟到响应不得写入新设备。

相关入口：`app/platform_asset_loader.py`、`app/trackunit_events.py`、`app/api/routes_xgss_research.py`、`extension/trackunit-fault-page.js`。

## 三、XGSS 与备件依据

- `app/xgss_direct_api.py` 使用既有获准认证读取同 VIN 目录、零件明细与二维图纸；`app/xgss_direct_collection.py` 负责查询范围、缓存、版本校验和原子保存。特定可回退错误才使用既有插件采集链。
- 返回的料号只能来自当前已保存资料；图纸按实际分类与 `capture_id` 关联，不借用其他分类图片。SVG 转换失败不能伪造图示成功。
- 主动重读可使用严格布尔字段 `force_refresh` 跳过缓存；仍保留身份、版本、活动研究、取消及容量检查。重读可以补图，不能丢弃之前已验证图片。
- `app/fault_part_grounding.py` 区分条件性备件、优先核查对象和历史参考。总线通信异常不能直接推导为电源或控制器需要更换；图册名称与位置本身不构成损坏证据。
- 旧建议未通过当前质量版本时保留原资料并要求重新分析，不能直接恢复为已验证备件。
- XGSS 目前读取范围为零件图册与二维图纸；不宣称已覆盖所有维修手册、多图分类或保养包。参考估价按有来源的用户单价计算，不是 XGSS 正式报价。

## 四、连续传感器与风险分析

- `extension/trackunit-sensor-page.js` 发现可见传感器并按页面上限分批导出 CSV；`extension/sensor-series-bridge.js` 核对设备、页面与回传范围。
- `app/sensor_series.py` 合并多通道数据，保留物理量、状态量、累计量和编码的不同含义；未知单位不推测，缺失值不补成零。
- 不同采样率按实际时间戳合并。异步行缺少 RPM 不等于停机；缺口拆段，不能跨缺口外推。
- 传感器风险分析及备件接续使用已保存的同设备证据，不能伪装成已发生的故障码。
- 当前输出是有证据的风险假设。故障发生时间、概率和剩余寿命尚未完成实车标定，不能由趋势或模型分数直接承诺。

## 五、配置与本机资料

- 外部服务配置、密钥和会话仅留在本机，按 README 配置，不写入前端、扩展、Git 或报告。
- `data/local/` 的原始导入、授权资料和运行缓存不随源码发布；克隆代码不会带入既有客户设备与现场记录。
- CEB 参考附件的归档与适用范围见 [CEB_FAULT_REFERENCES.md](CEB_FAULT_REFERENCES.md)，公开数据候选见 [OPEN_DATASETS.md](OPEN_DATASETS.md)。故障定义表不能直接充当真实故障事件或订购料号映射。
- 真实现场评估日志及扩展打包清单保留本机，不将其中的设备标识、客户采样或认证信息加入发布。

## 六、验证范围

自动化测试可验证来源、数据解析、身份隔离、故障分组、料号依据、图片绑定、缓存重试和请求取消。它们不能替代真实浏览器中的登录、页面导出及插件回传验证，也不能证明实际维修效果。

发布前按实际环境检查：Trackunit 当前设备与故障选择；Advanced Sensors 原生分批导出与回传；XGSS 图文读取与风险配件接续。邮件预览和实际送达分别验证，预览成功不能写成通知已发送。

## 七、继续开发时不要重踩的坑

1. 仅运行受影响的定向测试。通过后没有新增改动或未解问题，不反复重跑全量。
2. 页面“已连接”只表示连接状态，不代表故障、模型、XGSS 或邮件全部成功。
3. 不用手工导入的 CSV 或网页辅助采集代替新版扩展原生链路验收。
4. 不绕过 VIN、数据版本、活动研究、来源或图片校验来消除错误提示。
5. 恢复已有资料不能重复调用收费模型；需要重新分析时保留现有资料并走明确的重试操作。
6. 正式设备与合成夹具分开。合成信号不能与真实 VIN 拼接，也不能变成真实故障预测结论。
7. 停机零油压、不同步的传感器值和采集缺口必须结合工况解释，不能直接判故障。
8. 源码构建、局部测试、真实浏览器交互和维修效果属于不同验证层次，分别记录，不相互替代。
