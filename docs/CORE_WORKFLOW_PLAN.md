# 机联智检：故障推理与备件定位下一阶段计划

规划日期：2026-09-15。依据用户确认的产品方向及本轮源码审查。本文是待实施计划，不代表新增功能已完成；接口状态沿用历史核查记录，本轮未重新调用外部接口。

## 本阶段目标

交付可在网页和 Chrome 侧栏连续使用的流程：Trackunit 设备与故障信息 → 原厂资料检索 → AI 推断可疑部件 → XGSS 图册候选匹配 → 检查反馈后更新判断。

故障到部件、部件到图册条目的关系由 AI 建立，不要求用户提供完整 BOM 或预制故障—料号表。真实料号来自实际读取的资料条目；没有料号也可以形成可疑部件、检索词和下一检查。图册中存在某部件不代表已经确定它损坏。

首轮范围为 XE55U 与 E4030。E4030 是有原厂手册依据的测试场景，不能默认认定当前 Trackunit 机器实际发生了此故障。测试前绑定适用配置与资料版本；已有 TV12U 演示保留其独立机型和模拟属性。

## 可复用的现有能力

- `extension/panel.js` 与 `app/assistant_ui/platform-context.js`：设备 UUID 跟随、数据版本选择、草稿和切换隔离。现在主要关联本地实测缓存，实时同步须单独处理。
- `app/local_assistant.py`：设备快照、故障证据、趋势计算、DeepSeek 请求、报告保存、反馈输入。
- `app/assistant_ui/app.js`：报告、检查项、历史、备件表和导出。
- `app/xgss_handoff.py` 与 `app/assistant_ui/xgss-viewer.js`：取得并展示 XGSS 页面入口，尚未读取图册条目回传给 AI。
- `app/parts_catalog.py`：现有本地目录降为候选来源之一，查询无结果不再作为部件推理结束条件。

## 实施顺序与验收

### 1. 统一设备、故障和资料上下文

把本次调查固定为同一设备的 UUID、VIN/PIN、型号、配置、采样时间、数据来源、所选故障和用户现象。区分实测事件、人工报告、测试场景，以及接口失败和没有事件。

扩展目前仅支持 TV12U 的人工故障入口，按编码体系和资料版本处理 E4030、SPN/FMI 等；未经识别的代码仍可保存为用户报告，但不能套用另一机型的定义。自动同步仅接入实际可读字段，失败保留采样时间和明确状态。

验收：设备 A 切换到 B 后，故障、手册、候选、草稿分别归属正确；读取失败不显示“无故障”；XE55U E4030 可进入调查而无需伪装成滑移代码。

### 2A. 接入可检索的 XE55U 原厂资料

取得已授权的相关原文件，先处理故障表、E4030 排查章节、连接器表及必要图示。按手册 ID、机型/配置、版本、PDF 页码和原文片段建立本地索引。两向与四向配置分别管理。私有正文与索引留在本机忽略目录。

文字 PDF 提取文本和表格；扫描页使用本地 OCR 并核对代码、数字和表格关联。现有 DeepSeek 客户端发送文本，因此复杂电气/液压连线关系先采用经核查的局部关系，不将 OCR 文字冒充完整图纸理解。后续再扩展更多章节和图纸理解能力。

验收：查询 E4030 可返回相应配置手册的排查段落并打开原页；代码表的 SPN 与 FMI 不跨行配对；错误或未知配置明确标记适用范围。

### 2B. 验证并接入 XGSS 页面条目读取（与 2A 并行）

最先完成小规模可行性验证：用获准的目标 VIN 打开图册，确认页面设备身份，再读取一个相关分类的可见零件表，获得名称、料号、图号/序号和图册路径。此前其他机型图册的成功记录不能作为 XE55U 适配证明。

当前扩展只覆盖 Trackunit，需新增面向 XGSS 的页面读取适配。先验证实际页面结构和读取权限，再确定表格提取或经核对的 OCR 路径。会话地址和登录信息不进入 AI 上下文或持久报告。

由 AI 产生部件别名、所属系统和检索词，插件负责在图册中执行受限的搜索/分类读取，并把实际条目回传。第一轮支持用户选定分类或条目完成同一回传协议，随后验证自动检索。若页面暂不可读，部件推断继续，料号定位步骤明确未完成。

验收：至少一组真实图册条目进入助手，条目内容与页面一致；可从候选追溯分类和行位置；不会把另一 VIN 的行用于当前设备。仅获得跳转 URL 不算通过本项。

### 3. 实现 AI 部件推理与候选排序

在现有调查流程中增加手册检索、部件假设、图册读取、候选排序能力；支持按新证据进行有次数与时间上限的多轮查询。保留已有指标计算和引用校验，改掉“只有本地表命中才有推荐”的流程及遗留提示词。

输出分别保存：

- 故障证据：原码、编码体系、设备、时间、实测或人工来源。
- 部件假设：名称和别名、系统/位置、可能原因、支持与冲突证据、缺少的信息、待检查项。允许没有料号。
- 备件候选：实际条目的料号、名称、图号/序号、图册路径、VIN 上下文、匹配理由、尚待核实的适配信息。

检查步骤优先从适用手册提取并保留出处。程序校验候选料号属于本次实际读取集合、引用存在且设备一致；AI 决定推理和排序，不自行创造料号。优先级不包装成未经验证的故障概率。

验收：没有人工映射表时，E4030 仍能得到有原文依据的多个排查方向；可匹配真实候选条目；无匹配时保留部件假设与后续定位动作。既有旧入口中的映射表前置要求同步调整。

### 4. 串通网页、插件与反馈续查

复用现有界面和徐工蓝视觉，主操作顺序统一为：当前设备 → 故障/现象 → 可疑部件与依据 → 图册候选 → 检查反馈。网页展示完整材料，侧栏提供紧凑操作，两者共享同一调查记录。

点开部件可看手册出处、匹配理由和 XGSS 位置；无料号的部件也有明确下一步。关联选中的实测故障或人工故障进入 XGSS，不能只读取人工输入字段。

反馈后显示哪些假设被保留、降低优先级或新增，以及依据哪条检查记录；外观未发现异常不能等同电气测量合格。保留前后报告与未完成检查。切换设备时处理中请求不能污染新设备。

验收：用户不需要反复复制 VIN；完成一次分析、查看候选、输入反馈、再次分析和导出；网页与实装 Chrome 侧栏分别跑通。

## 第一份可查看的交付与完成标准

第一里程碑：在现有界面打开 XE55U 的 E4030 调查，看到按配置检索的手册原文、可疑部件和判断理由；XGSS 侧至少完成真实条目读取验证。报告清楚区分当前设备数据与测试输入。不能以静态预设回答替代实时 AI 软件验收。

本阶段最终交付：更新后的网页和 Chrome 插件、可复用的资料导入/检索与图册读取适配、部件推理和匹配流程、一次完整案例报告与演示、对应安装说明和验收记录。源码可分发；内部原文、真实缓存和账号资料保持本机存放。

关键验证覆盖：正常闭环、无料号、错误配置、故障接口失败、XGSS 不可读、设备快速切换、反馈改变判断。测试还需拒绝模型新增不存在的料号/引用，并验证历史可以重开和导出。网页通过不代替实装侧栏通过；API 工具链通过不代替实际维修效果。

## 范围与后续

当前资源集中投入上述单机流程。车队大屏、更多机型、完整图纸自动理解和故障预测扩展安排在本阶段验收之后；既有模块保留，避免重建网站或引入第二套诊断后端。Trackunit 故障权限与 XGSS 故障参数问题作为独立联调项推进，人工报告和通用图册入口支持其余环节先完成。

按里程碑记录已通过项与实际耗时，再安排后续，不用代码行数或历史测试总数代替用户可见的完成程度。
