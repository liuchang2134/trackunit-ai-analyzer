# 机联智检

辅助已有车联网平台处理设备故障的工具：网页工作区 + Chrome 侧栏插件。AI 分析默认使用 DeepSeek API，关闭深度思考；设备资料、草稿和检查记录保存在本机。Gemini 和本地 Ollama 仍可手动配置。

## 比赛展示界面

网页与侧栏采用同一套深石墨工业风：徐工蓝主按钮、青色状态线、紧凑设备参数网格。设备信息、运行趋势和 AI 排查为主入口；版本与来源详情、分析设置、草稿和近期请求记录可按需展开。模拟标识、真实错误、缺失数据和诊断待核验状态继续保留。已安装插件需要重新加载到 0.9.1。

## 当前设备自动关联

当前网页构建：`20260915.20-docs-index`；Chrome 插件源码：`0.9.1`。工作预览在 [8890 设备排查](http://127.0.0.1:8890/assistant-ui/)。升级后在 Chrome 扩展管理页重新加载插件，再重新打开侧栏；仅点击侧栏“重新连接”不会更新插件代码。

插件跟随当前 Trackunit 详情页的设备 UUID，并提取标签页标题中显示的设备编号作为查询提示。网页优先载入该机已有实测数据——此时**不等待**面板确认编号，真机数据在本机就直接按当前 UUID 显示；只有需要远程读取时才等待该确认。没有本地版本时，优先用编号查询 AEMP 单机快照，并要求返回的 `metadata.assetId` 与页面 UUID 完全一致；该编号不可用时（含 401/403）仍继续走车队检索，不会整次作废。没有提示时尝试 Assets 接口及最多 3 页的 AEMP 车队快照；触及页数上限时显示"已查 N 页 / 共 M 页"，不提示重试，因为重复读取会得到同样结果。只独立保存目标设备，不覆盖整队缓存；身份冲突、缺少有效采样时间或访问失败时显示原因。本次自动读取不调用 AI 或故障事件接口。

## 流式 AI 与停止

AI 排查走 `POST /assistant/investigate/stream`：一个请求承载整次排查，按真实阶段推送进度（准备、读取设备快照、读取故障事件、计算工时与怠速、第 N 次模型决策、整理报告）。只有通过校验的完整报告才会显示，**局部模型输出不会渲染成诊断**。停止会中断请求并由服务端取消调查，不再发起后续模型调用；重试先中止仍在运行的请求再重新开始。切换设备会中止在跑的分析，旧设备的迟到事件不会落到当前设备。一次已经在传输中的模型请求仍会在服务端完成——界面按此表述，不声称在上游中断了单次请求。

网页内进入演示会同步暂停插件跟随；点击“读取当前设备”或恢复跟随时返回设备排查，按钮与状态说明保持一致。未知设备的读取有次数、时间及失败退避限制；切换设备或分析期间的旧响应不会回填到新设备。0.6.1 会跳过不支持上述流程的旧服务，再检查另一个本机端口。

## XE55U 的首个故障案例

选定产品为 **XE55U 柴油液压挖掘机**，首个测试故障为 **E4030 J1939 总线通信故障**。当前设备已有导入的 Trackunit 历史工时；E4030 单独标记为测试输入，不写入或伪装成真实 Trackunit 故障事件。

1. 选择 XE55U，在「运行数据与故障记录」点击「测试 E4030」。
2. 核对来源和配置；未知时保留「待核对」，点击「开始分析」。
3. DeepSeek 结合设备上下文和手册摘录，生成可疑部件、依据页码、图册检索词与待检查项。
4. 记录检查反馈后继续分析，查看反馈对判断的影响；保存和导出报告。
5. 在对应 VIN 的 XGSS 图册中打开零件明细，用新版 Chrome 插件「读取当前 XGSS 图册」读取可见条目，再「结合图册继续分析」。料号只取实际读取的图册条目，关联与排序由 AI 完成。

手册知识当前仅为已核查的 **XE55U.00III / EWMEN55U-A02 / PDF 第 286–287 页**摘录，保存在本机私有目录；不是整本 PDF 已导入，也未完成四向铲版本的知识导入。实际 Chrome 已在 8890 完成测试：首次真实 DeepSeek 分析显示用时 13 秒，返回 4 类可疑部件、2 页依据；保存明确标注的模拟检查反馈后，续查显示用时 6 秒，逐项说明反馈没有排除故障。历史重开、Markdown 实际下载和 390 像素窄屏报告也已验证。这些时间是单次软件流程观测，不代表诊断准确率或固定响应时间。

**尚未完成真实料号闭环：**当前 XE55U 的 VIN 尾号 02003 请求 XGSS 时，HTTP 200 的业务内容返回 `success=false`，提示 VIN 不存在，未读到该机器的真实零件条目。扩展读取能力已有自动化测试，但 Chrome 中新版插件的实际重载及图册读取验收尚未完成。完整状态见 [当前验收状态](docs/PROJECT_ACCEPTANCE_STATUS.md)。

## 启动

Windows，使用 Python 3.12，在项目根目录的 CMD 运行。首次克隆：

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-xgss.txt
copy .env.example .env
start_local.cmd --port 8890
```

已有环境直接运行 `start_local.cmd --port 8890`。本机检查用 `start_local.cmd --port 8890 --check-only`；不会停止或重启已有进程。演示无需填写密钥；真实 AI 分析需要在 `.env` 配置 `DEEPSEEK_API_KEY`。默认 `AI_PROVIDER=deepseek`、`DEEPSEEK_MODEL=deepseek-flash`，只连接 DeepSeek 官方地址。修改配置后重启后端；网页和插件共用后端密钥，无需分别填写。

网页入口：[设备排查](http://127.0.0.1:8890/assistant-ui/)。Chrome 插件直接加载项目中的 `extension` 文件夹，连接设置选择8890，详见 [插件说明](extension/README.md)。不需要单独编译当前网页和插件。

## 复核 AI 的依据（可重复运行）

AI 的引用是否真的指向已读取的证据，可以自己跑一遍核对；脚本只读本机记录、不调用模型：

```bat
.tmp\venv\Scripts\python.exe scripts\evaluate_ai_grounding.py
```

它在 `docs/evaluation/` 写出 JSON 与 Markdown：扫描多少条记录、其中多少条真的跑过模型、共核对多少条引用、有多少条悬空，并附每条运行的明细与所用代码的哈希。**这里度量的是引用能否对上证据，不是诊断正确率**；准确率需要带标签的验证集，本机没有，因此不作声明。
